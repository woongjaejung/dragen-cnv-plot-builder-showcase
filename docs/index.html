Why it exists

A copy number, a quality score, and a filter tag do not settle the question

Per exon
Every exon in the called region as its own point, not the segment average — a clean shift across a whole gene looks nothing like one noisy capture target.
The batch
The same targets in every other sample, on the same axis. A dip shared by the whole batch is a capture or GC artifact, not a deletion in one patient.
Copy states
Reference lines at diploid (1.0), het deletion (0.5), and het duplication (1.5).
Controls
No-template controls auto-detected by regex and rendered dashed with X markers.
The caller
Both PASS and filtered calls with filter explanations — so a rejected call remains visible to inspect.

Single-pass v4 architecture

In-memory multi-core pipeline, one offline HTML artifact

  1. Parallel BGZF & index load

    Decompress all sample folders concurrently across CPU cores while loading the pre-indexed exon table.

    • *.dragen.tn.tsv.gz (MultiGzDecoder)
    • *.dragen.seg & *.dragen.cnv.gff3
    • 13.7 MB lossless GCV4 exon cache

  2. O(targets) interval join

    Resolve unique panel coordinates once per batch via 100 kb genomic bins and attach segments and calls in memory.

  3. Lazy V8-safe HTML stream

    Serialize each gene into its own lazily parsed script tag so even 50+ exome batches stay under 0.2% of V8's string limit.

One self-contained interactive HTML file opens offline, zero Python or CDN dependency
